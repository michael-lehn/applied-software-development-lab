# Applied Software Development Lab

Teaching materials for the undergraduate course **Applied Software Development
Lab** (*Praktikum Anwendungsorientierte Softwareentwicklung*) at Ulm
University, Germany. This repository is the English edition of the German
original in
[michael-lehn/avr-bare-metal](https://github.com/michael-lehn/avr-bare-metal).

The course starts at the lowest level of software: machine code, typed in by
hand, that makes an LED blink on an ATmega328P microcontroller — without the
Arduino framework, libraries, or an IDE. Each lab session adds one layer of
abstraction, until at the end of the semester students play a Python game of
their own that is controlled by a microcontroller-based game controller.

## Final project

The goal of the semester is a self-written game in Python that is controlled
by a custom game controller: an ATmega328P that reads a **BNO055** orientation
and acceleration sensor and a **push button** and sends the data to the game
over the serial interface. The video shows one result, a hybrid of Breakout
and Space Invaders:

## Educational concept

The course moves from hardware-oriented programming to platform-independent
software development, one layer per step:

**Machine code → Assembly → C → Build tools → Serial communication → Python →
Hardware-integrated game**

1. **Machine code.** Students write an Intel HEX file byte by byte, flash it
   with `avrdude`, and measure the resulting signal with an oscilloscope. The
   timing is derived from the clock cycles of each instruction and then
   checked by measurement.
2. **Assembly language.** The same program is written in assembly language.
   Delay loops with one, two, and four registers show how the cycle count of
   a loop determines the blinking frequency.
3. **Bare-metal C.** The program is rewritten in C without any framework, and
   the assembly code generated by the compiler is compared with the
   hand-written version.
4. **Build tools and version control.** Makefiles automate the toolchain;
   `git` is used to manage the students' own code.
5. **Serial communication.** The microcontroller exchanges data with the PC;
   students write a Python program that reads the serial interface.
6. **Python and object-oriented programming.** A Breakout-style game is
   developed step by step with Pygame. Classes are introduced when the code
   needs them, followed by refactoring into modules.
7. **Hardware-integrated game.** A push button, a potentiometer, and finally
   the BNO055 sensor control the game.

Recurring principles of the handouts:

- **Practice and background are separated.** The lab handouts are step-by-step
  instructions for the lab session; the project companion explains the
  technical background. Both can be read independently and in either order.
- **Predict, then measure.** Students first calculate what a program should
  do (e.g., pulse widths from clock cycles) and then verify it with the
  oscilloscope.
- **Errors are part of the workflow.** The handouts show how to recognize an
  error and which step to go back to.
- **Problem before solution.** A tool or language feature is introduced
  together with the problem it solves.
- **Room for own ideas.** Step-by-step instructions are given for classic
  games such as Breakout, but students may develop their own game.

The course was planned for 14 sessions; because of public holidays, 11 took
place, hence the 11 handouts.

## Repository structure

```
handouts/       LuaLaTeX sources of the lab handouts
supplementary/  LuaLaTeX source of the project companion and its figures
figures/        Images and TikZ figures (one directory per handout, plus shared/)
tex/            Document class and Lua helper shared by all handouts
pdf/            Generated PDFs
examples/       Assembly and C programming examples
```

## Building the PDFs

Requirements: TeX Live with LuaLaTeX and `latexmk` (the fonts TeX Gyre Heros,
Fira Mono, and Noto Color Emoji are part of TeX Live) and GNU Make.

```sh
make            # build all documents and copy the PDFs to pdf/
make handouts   # lab handouts only
make clean      # remove intermediate files in build/
```
